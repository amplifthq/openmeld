## Skills

A local coding tool can have its own installed Skills and instructions. **Team → Skills** manages workspace Skills; do not assume a Team Skill is automatically installed in every local tool.

Name the Skill you want, confirm that the selected tool can read its instructions and required resources, and follow that tool’s supported setup. Use the [Team Skills guide](/docs/team/skills) when creating or maintaining a shared procedure.

## Plugins and files

Check which tools and connections the local execution can access. [Organization and personal Plugin connections](/docs/team/plugins) keep their own identities and permissions. A local provider login is separate from signing in to OpenMeld.

For repository work, confirm the [working folder](/docs/work/projects) and the Agent’s access settings. A file shared in a Space and a file at a local disk path are not automatically the same copy. See [Files](/docs/work/files).

## Routines

1. Confirm that the computer is connected and the local tool is available.
2. Open **Team → Routines** and select the Local Agent as executor.
3. State the intended folder, inputs, output, and permitted actions.
4. Set the schedule, timezone, and result destination.
5. Review the first Run and its actual output.

Follow [Routines](/docs/work/routines) for all creation and maintenance controls. The computer must be available at execution time. Interactive login or approval can block unattended work.

If nothing runs, read [Routine skipped](/docs/help/routine-skipped). If work ran but no answer appeared, use [Routine result missing](/docs/help/routine-result-missing).
