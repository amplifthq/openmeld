---
title: Projects and folders
description: A Project names shared work; a folder is where one computer runs it.
---

A Project gives your Organization a shared identity for work. A local connection tells one computer which folder belongs to that Project. The Project itself is not a checkout.

```text
                   Launch website (Project)
                    /                    \
          Your computer             Teammate's computer
          Your checkout             Their checkout
```

## Which choice controls what?

| Choice | Purpose |
| --- | --- |
| Project | Identify shared work in the Organization |
| Local folder connection | Connect an existing directory on one computer |
| Default folder | Choose that computer's default connection for the Project |
| Agent's Default Project | Choose a Project for future work using that preference |
| Working folder | The actual directory used by one execution |

Changing a Default Project does not move an existing session. A path that works on your laptop does not establish a connection on another computer.

## Before code work

Check the selected Agent, computer, Project, and folder together. If the folder moved, reconnect it. Do not create another Project just to hide a missing connection.

An isolated task folder is a separate working copy. It does not automatically contain uncommitted edits or ignored configuration from your original checkout. Tell the Agent which committed revision and inputs it needs.
