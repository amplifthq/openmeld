---
title: Understand and manage memory
description: Keep useful context while knowing which audience it belongs to.
---

Memory helps Center Agent retain useful context across conversations. It is separate from the messages and files that record the work itself.

## Member and Organization memory

**Member memory** belongs to you within one Organization. Eligible private Center Agent conversations can contribute to it.

**Organization memory** is shared workspace context. It is enabled by default unless changed. Shared conversations do not automatically become saved memory; explicit shared facts follow the Organization's memory policy.

A preference stated in a shared conversation is not automatically a private saved preference.

## Inspect the controls

Open Center Agent and find **Memory** in its navigation or menu. Review the scope before changing a memory setting or clearing memory.

Clearing your member memory does not delete the conversation, its files, or shared Organization memory. Deleting a message is also not the same operation as clearing memory.

## Give durable instructions the right home

Use [Skills](/docs/team/skills) for repeatable procedures. Use [Team Knowledge](/docs/team/knowledge) for approved reference information.

For important work, name the current source and ask the Agent to read it. Do not assume an old remembered fact is still correct.

## Be explicit about audience

Before asking the Agent to retain information, decide whether it is personal or shared. Do not place private details in a team conversation just to make them easier to remember.

A connected messaging account and current access rules still apply when you talk through Slack, Lark, or Feishu.

## Check a claim about memory

If the Agent says it remembers something, ask which source or context it used when that matters. A statement in a reply is not a substitute for checking a saved record or a current policy.
