# Settled Decisions

## Agent Context

- Purpose: Index the decisions Felix has already made so agents do not
  relitigate them, "helpfully" optimize them away, or execute stale plans that
  a decision reversed.
- Read this when: You are about to propose a rename, an architecture change, a
  dependency swap, or a cleanup that feels obvious — check it was not already
  decided.
- Update this when: A decision is made or reversed. Change the entry in the
  same PR as the change itself. This index states the decision in one line;
  detail lives with the linked owner.
- Do not use this for: Rules (owner docs), roadmap, or open questions. Only
  settled calls belong here.
- Source of truth: This file owns the settled-decision index. An entry that
  conflicts with an owner doc means one of the two must be fixed in the same
  PR.

2026-10-28: An Organization Owner may change another Owner to Admin or Member
after explicit confirmation, while another Owner remains. The current Owner's
own row stays read-only. Auth retains its native permission checks; PostgreSQL
atomically refuses writes that would leave retained members without an Owner.
This supersedes the Owner-transfer UI deferral only for Owner demotion;
promotion and broader transfer flows remain deferred. See
`product/organizations-and-center-agent.md`.

2026-10-27: Owners can rename default Agent Profiles as well as additional
Profiles. This supersedes the MemberAgent program's default-name lock in
response to indistinguishable Agent names. Harness assignment remains fixed;
sync preserves chosen names, and mention candidates show the owner. See
`product/agent-profiles.md` and `product/space-collaboration.md`.

2026-10-21: New Space Durable Objects are created with location hint `enam`,
next to the PostgreSQL primary; existing Spaces are not moved and no
jurisdiction is set. See `architecture/data-and-observability.md` (Space
object location).

2026-10-18: The **MemberAgent program** restructures local Agents around
`MemberAgent` (organization × owner × harnessKind, derived state, no status
column) → Agent Profile → Session. Vocabulary: MemberAgent / Harness / Agent
Profile / Session; "tool" is not used for a harness. Remote Agents are `hosted`
MemberAgents; Profiles cannot change harness; the default Profile is named
after the harness; Sessions are DM Spaces by pairKey or Execution Contexts;
every Wake has a human root requester and sensitive operations check that
root; CLI-credential confirmation applies only while the computer runs a
non-owner-rooted task; quota numbers stay owner-only; the permission-mode
advisor ships in Phase 1; all work lands in one draft PR. Detail:
`design-plans/member-agent-program.md`.

2026-10-21: Platform-funded hosted AI admission reserves a conservative
per-request credit hold against the workspace's monthly allowance in Core's
usage ledger, under a per-workspace lock. Receipts now participate in admission;
the OpenRouter native key limit remains the backstop. This is a paid-launch
prerequisite. See `engineering/ai-billing.md#admission-and-credit-holds`.

2026-10-19: The hosted AI funding source contract supports monthly Free credits
for a creator's first workspace and a workspace OpenRouter key. This supersedes
the BYOK deferral and environment-owned BYOK funding alias in older decisions.
Core owns funding admission; OpenRouter owns native spend limits. See
`engineering/ai-billing.md` for the current policy and rollout boundary.

2026-10-15: The Web primary rail is **Inbox / Spaces / Team / Routines**.
Team retains **People / Agents / Files / Skills / Plugins**. Contextual
sidebars follow their content: members in People, the current Agent list in
Agent detail, and locations in Files. Skills, Plugins, and Routines use their
in-page controls without a member sidebar. This supersedes the earlier Team
tab order and placement of Routines under Team; routes, scope, and authority
remain unchanged. See `clients/web.md` and `clients/shell-and-settings.md`.

2026-09-26: Plugin setup should be available from an Agent conversation without
leaving that OpenMeld page. Reuse the existing provider connection and Agent
access owners across Plugins, Onboarding and the conversation entry; preserve
personal versus shared intent and require the current user's provider consent.
The connection form is not a second authorization or task-completion authority.
See `clients/web.md` and `product/remote-agent-runtime.md`.

2026-09-24: The Center Agent system default is Claude Opus 5.5 at `medium`
reasoning. Personal Remote Agents share its hosted model list but have a
distinct GPT-6 Sol system default at `medium`. An unset Binding follows the
appropriate catalog default on its next admitted turn; explicitly selected
models and already frozen turns remain unchanged. This supersedes the earlier
GLM 5.3 Flash Center Agent default below. See
`product/agent-model-selection.md` and `product/remote-agent-runtime.md`.

2026-09-18: Organization Skills management belongs to Team, after People,
Agents, and Plugins, at `/o/{orgSlug}/skills` and its Skill detail route. This
supersedes the older Center Agent Skills navigation entries below: legacy
Skills URLs redirect with replacement rather than being removed. Center Agent
conversational tools, the single Organization Skill model, Core authority,
maintainer limits, CLI contracts, and runtime consumption remain unchanged.
See `product/organization-skills.md` and `clients/web.md`.

2026-09-14: Context-enabled Local Agent Profiles use one Work Coordinator with
up to five independent reservations and one writer per Execution Context.
This supersedes the one-slot FIFO and Profile-wide native conversation as the
execution model for migrated Profiles. Binding remains the connection/settings
owner; RuntimeCoordinator remains execution authority. Legacy work drains under
its original identity, and serial rollback preserves Context ownership. Local
Space Action receipts confirm local storage only. See
`product/agent-profiles.md`, `architecture/agent-transport-contract.md`, and
`architecture/local-openmeld-service.md`.

2026-09-09: Every managed Center Agent, including Personal Workspace Center
Agents, belongs to its Organization. Creating members are audit actors, and
current owner/admin permissions govern configuration and Pause/Resume. This
supersedes personal Binding ownership and creator-exclusive operating controls;
it grants no inherited private-content access. See
`product/organizations-and-center-agent.md` and `product/agent-profiles.md`.

2026-09-08: Ordinary members may create personal Remote Agents with per-Agent
model selection. They reuse Agent Profile identity, ordinary DM/Space
membership, and the native execution service; they do not inherit Center Agent
designation, memory, or administration. Same-owner Agents may explicitly Wake
each other in one Space. Advanced session binding, fork, migration, and personal
Routines are outside the first release. This supersedes the former deferral of
ordinary native Agent creation; the hosted-workstation R2 freeze is unchanged.
See [Remote Agent Runtime](product/remote-agent-runtime.md#personal-native-agents).
