# OpenMeld Glossary

## Agent Context

- Purpose: Define the stable OpenMeld vocabulary that coding agents should use
  consistently across code, docs, schemas, APIs, and product copy.
- Read this when: You are naming OpenMeld concepts, writing docs, reviewing
  terminology drift, or changing code that touches Wake execution, setup,
  readiness, local service, Space collaboration, Feedback, Binding, claim, or
  projections.
- Update this when: A durable OpenMeld term changes meaning, a new cross-cutting term
  becomes part of the architecture, or an existing code anchor stops
  representing the term.
- Do not use this for: Detailed architecture rules, migration plans, debugging
  runbooks, product copy catalogs, raw traces, or temporary investigation notes.
- Source of truth: This file owns short vocabulary definitions only; scoped
  architecture and product documents remain authoritative for rules.

## Terms

| Term | Definition | Code anchor |
| --- | --- | --- |
| carrier | The carrier is the local OpenMeld Service layer that owns the daemon-facing entrypoint, adapter container, socket session, heartbeat, reconnect, and local dispatch plumbing needed to carry accepted work to local agents. | `runtime/local-service/src/index.ts:1` |
| continuation | Continuation is the decision about whether a local execution context is a fresh context, a stable resume, an explicit heal, or an implicit rotation that should warn. | `runtime/local-service/src/dispatch-continuity.ts:1` |
| lane | A lane is the local serial execution key that keeps work for the same Agent Controller conversation together, falling back to the Agent Profile when no controller conversation exists. | `runtime/local-service/src/dispatch-queue-routing.ts:81` |
| generation | Generation is the monotonically checked connection version for a ready wake route, used with daemon session and lease evidence to prove the route is still the one that accepted the work. | `packages/agent-runtime/src/agent-wake-availability.ts:71` |
| lease | A lease is the daemon-session ownership fence for a device and lane; reconnects or takeovers either keep or advance the lease epoch, and result acceptance checks the expected epoch. | `packages/agent-runtime/src/lease-fencing.ts:1` |
| dispatch vs Agent execution | A dispatch is the cloud Wake work item and ledger identity, while an Agent execution is the local runtime unit carried under that dispatch. Historical wire fields may still say `task`; that compatibility literal does not name the user-visible Center Agent Task product. | `packages/schemas/src/schemas/daemon/dispatch-queue.ts:88` |
| bootstrap | Bootstrap is the initial Space load contract that gathers the status, members, history, and threads needed to open a Space surface. | `services/gateway/src/routes/rpc-http.bootstrap.ts:17` |
| composition | Composition is the act of combining owner-specific facts into a derived plan or projection without becoming the owner of those facts. | `packages/start/src/planner/onboarding-plan.ts:1` |
| claim | A claim is the side-effect-free Core eligibility decision that says whether known facts are sufficient for Core to consider execution, while explicitly not granting success or starting work. | `packages/agent-runtime/src/claim-eligibility.ts:95` |
| binding | Binding is the Agent Profile to runtime execution target relationship, including routability, execution target, dispatch-readable facts, reason codes, and diagnostics. | `packages/agent-runtime/src/agent-profile-binding.ts:80` |
| projection | A projection is a queryable read model copied from an owner truth, such as Space Index membership rows projected from Space truth, and it must not become the authority that created the fact. | `services/core/src/space-index/space-index-repository.ts:344` |
| Profile Directory | Profile Directory is the internal permission-scoped identity answer for people and Agent Profiles. It is not a user-facing Directory destination, is semantically independent, and never waits for or decides Wakeability, Activity, Wake Progress, Wake Outcome, or Recovery. It may share a bounded request with other owner answers. | `developing/product/agent-profiles.md`, `developing/architecture/shared-contracts.md` |
| Wakeability | Wakeability is Core's current answer to whether an Agent Profile can accept a new Wake in the requested context now. The public verdicts are **Available**, **Checking**, **Offline**, and **Unavailable**. Current identifiers such as `AgentExecutionReadiness`, `AgentWakeAvailability`, `AgentExecutionStatusProjection`, and `/execution-readiness` are compatibility implementation names for this concept during migration, not separate product terms. | `packages/agent-runtime/src/agent-execution-status.ts:129`, `packages/agent-runtime/src/agent-wake-availability.ts:1` |
| Wake Progress | Wake Progress is the current lifecycle of one exact Wake, including real queue, delivery, waiting, and running evidence. It does not decide later Wakeability or general Agent Activity. | `developing/architecture/agent-transport-contract.md` |
| Wake Outcome | Wake Outcome is what happened to one exact Wake: reply, stopped outcome, failure, or publication uncertainty. It remains visible independently of current Wakeability. | `developing/architecture/agent-transport-contract.md` |
| Recovery | Recovery is a shared, stateless resolver for a viewer-permitted next action. Current-owner facts may produce current-state actions; one exact Wake Outcome may produce only outcome-scoped actions. Recovery owns no state, stored projection, or blocker verdict. | `packages/agent-profile/src/reply-recovery.ts:1` |
| Opportunity | An Opportunity is one concrete, evidence-backed way OpenMeld could help one verified member achieve a better result. It owns the member's recommendation decision but grants no action authority. | `developing/product/opportunities.md` |
| Recommendation | A Recommendation is the Center Agent's presentation of one Opportunity in a conversation or existing attention surface. It is not a second stored product object, a broadcast, or completed work. | `developing/product/opportunities.md` |
| Inbox | Inbox is a member-private, workspace-scoped attention surface for relevant updates and work that needs that member. An Inbox item is durable; browser and email notifications are optional deliveries of that item. Inbox owns read and clear state, while each source owns business resolution. | `developing/product/inbox.md` |
| Inbox item | An Inbox item is one deduplicated recipient-specific projection of a source event, classified independently by attention (`update` or `action_required`) and importance (`normal` or `urgent`). | `developing/product/inbox.md` |
| notification | A notification is an optional browser or email delivery of an Inbox item. It is not a second Inbox, unread store, or source of truth. | `developing/product/inbox.md` |
| Feedback Inbox | A Feedback Inbox is an organization-owned destination for Feedback Issues, exposed for submission through a random, non-enumerable, rotatable `inboxKey`. | `packages/db/src/core/feedback.schema.ts:3` |
| Feedback Issue | A Feedback Issue is one bounded product-feedback submission stored without triggering an agent. | `services/core/src/feedback/application/feedback-issue-service.ts:66` |
| Directory | Directory is the first-level workspace destination whose stable secondary navigation is **People \| Agent Profiles**. People is the single human-member directory and owns the role-gated invite action; Agent Profiles is the single home for the AI teammates that members manage. In a personal workspace, People shows the current member plus guidance to create an Organization for collaboration. | `developing/clients/web.md` |
| Space File | A Space File is a Space-owned shared file with one stable identity and immutable content revisions. Its name and folder placement may change without changing that identity. It is not an Organization Document, a message Attachment, or a file in the Center Agent Computer. | `services/core/src/space/infrastructure/sql/space-file-repo.ts` |
| Space Folder | A Space Folder is Space-owned placement for Space Files and child folders. It has no independent permission policy; access always comes from the containing Space. | `services/core/src/space/infrastructure/sql/space-file-repo.ts` |
| Space File Revision | A Space File Revision is one immutable content version of a Space File. A writer must name the base revision it read, and Space rejects a stale write instead of overwriting newer work. | `services/core/src/space/infrastructure/sql/space-file-repo.ts` |
| Activity | Activity is the first-level Web label for Agent Activity, the privacy-safe visibility product for local coding-agent sessions. It never means Wakeability, Wake Progress, the Center Agent Audit Log, or the audit journal. | `developing/product/agent-activity.md`, `developing/clients/web.md` |
| Organization settings group | The Organization settings group is the Settings section for the selected Organization and contains **General**. Its visible label is the Organization's stored name, including for the personal Organization. Every member can see it, mutations remain role-gated, and its label carries the current role badge. Center Agent-owned configuration lives in the Center Agent product. | `developing/clients/web.md` |
| Personal settings group | The Personal settings group is the account-scoped Settings section: **Account, Computers, Appearance, Notifications, Privacy**. Its structure and account scope do not change when the selected Organization changes; Notifications owns delivery preferences, while Privacy links to the current Center Agent Memory page for member-memory erasure. | `developing/clients/web.md` |
| Routine | A Routine is an organization-owned recurring instruction for the designated Center Agent, with an explicit schedule, IANA timezone, and target Space. The lower scheduled tasks pathway is an internal implementation term, not a second product object. | `packages/db/src/core/routine.schema.ts:12` |
| Run | A Run is one durable Routine scheduling or execution record. It normally represents one occurrence; one aggregate skipped Run may summarize a bounded range of missed occurrences. | `packages/db/src/core/routine.schema.ts:86` |
| Organization Skill | An Organization Skill is one optional Organization-owned portable Agent Skills bundle that teaches the Center Agent and explicitly selected local agents a reusable way of working. Required product behavior and internal playbooks are not Organization Skills. | `developing/product/organization-skills.md` |
| Organization Skill Release | An Organization Skill Release is one immutable, digest-addressed version of a complete Organization Skill bundle. Admitted Center Agent turns and delegated local tasks remain pinned to exact releases. | `developing/product/organization-skills.md` |
| Skill Maintainer | A Skill Maintainer is a current Organization member assigned permission to edit and save one Organization Skill. The role does not grant catalog installation, enablement, restoration, removal, or maintainer-management authority. | `developing/product/organization-skills.md` |
| Message channel | A Message channel is a two-way surface where people or systems message the Center Agent and receive its reply. It owns routing and sender identity plus only explicitly approved bounded reads needed for that conversation surface; it does not grant general provider-data or business-action access. Channels are managed once under **Center Agent → Channels** in the current workspace. | `services/core/src/remote-agent/remote-agent-slack-signal-service.ts:1` |
| connected Message Channel member | A connected Message Channel member is a human participant whose internal relationship to the current Organization is established by its connected Slack, Lark, or Feishu workspace, but whose provider account is not linked to an OpenMeld member identity. The person receives ordinary-member capabilities that need no personal ownership, OpenMeld role, or represented-human authority. This state never creates Better Auth membership or a Human Profile. `anonymous_member` remains only a mixed-version wire literal. | `packages/schemas/src/schemas/runtime/remote-agent-turn-envelope.ts`, `developing/product/organizations-and-center-agent.md` |
| Message Channel Identity Link | A Message Channel Identity Link is the canonical exact mapping from one provider-scoped user identity to one current OpenMeld user in the same Organization. It is authority-bearing and may be created only by an exact approved match source or an authenticated Identity Link Confirmation. | `services/core/src/remote-agent/infrastructure/d1/slack-user-identity-link-repo.ts`, `services/core/src/remote-agent/infrastructure/d1/lark-platform-identity-link-repo.ts` |
| App | An App gives the Center Agent scoped read or action access to an external system. It is independent from a Message channel even when both use the same provider. | `services/core/src/connectors/connector-connection-repository.ts:1` |
| member app connection | A member app connection belongs to one member's external identity inside one Organization and may be executed only for that verified member. Organization visibility or revocation rights do not make it shared. The member manages it under **Center Agent → Apps** as **Your access**. | `services/core/src/connectors/connector-connection-repository.ts:1` |
| shared app connection | A shared app connection is Organization-controlled App access that owners and admins manage for all members and unattended Routines. It still names the human external identity used to authorize provider actions. It is managed under **Center Agent → Apps** as **Organization access**. | `services/core/src/connectors/connector-connection-repository.ts:1` |
| Navigation Action | A Navigation Action is a structured `{ target, label, url }` presentation value that lets the Center Agent link to one canonical OpenMeld destination in the current Organization. It is built from Core-owned Organization Web context and shared route constructors; it grants no authorization and the model never constructs its URL. | `packages/schemas/src/navigation-action.ts:1`, `developing/architecture/shared-contracts.md` |
