### Recover transient local sign-in reads

Fixed · v0.3.103 · authentication · cli · spaces · files

OpenMeld now retries one temporarily unavailable saved sign-in read before it
blocks a command, so a brief local credential-store failure does not
unnecessarily stop Space file work. If the saved sign-in remains unavailable,
OpenMeld keeps the diagnostic reason and sanitized lower-level cause in Agent
View and `--json`, then asks the caller to retry or inspect authentication
status instead of incorrectly claiming that the sign-in is invalid. Unexpected
credential-read exceptions follow the same unavailable path instead of being
silently treated as a missing session. Expired, revoked, mismatched, and
genuinely invalid sessions still fail closed.

Evidence: pr:251, pr:253, commit:2ca575653b5cdc0fc646cf6da3e93b3aa4475db2, commit:41ddadfb5064b631358a29984f172ef9893a9af2, workflow:32815108186, workflow:32816201983

### Recover a Mac with a fresh setup command

Fixed · v0.3.95 · computers · cli · service

Fresh setup commands on supported Macs now use the normal macOS Keychain
without requiring a restricted app entitlement. If Keychain is temporarily
unavailable or does not answer within five seconds, OpenMeld stops waiting,
clearly warns the user, keeps the session in private local storage, and finishes
reconnecting the computer. It does not keep retrying Keychain in the same
process. A later successful setup or login automatically moves the session back
to Keychain. OpenMeld Service also reuses its loaded session instead of
repeatedly querying secure storage while it is running.

Evidence: pr:218, pr:219, commit:18f0b1c004955828f9d7cc64c122b0588a235d1b, workflow:32727645216

### Stop background Keychain authorization windows

Fixed · v0.3.96 · computers · cli · service

OpenMeld no longer opens macOS Keychain password dialogs while local agents are
working in the background or while setup is recovering the computer. Normal
Keychain access stays silent. If macOS requires approval, OpenMeld stops the
Keychain operation immediately, uses its protected local fallback during setup,
and leaves no waiting helper or orphaned password window behind. Developer and
npm CLI paths also stop immediately instead of launching macOS's interactive
`security` tool, so parallel local work cannot queue repeated password dialogs.

Evidence: pr:222, pr:223, commit:9cea7139ade576121d8dd46bade2531b71859881, workflow:32747450190
