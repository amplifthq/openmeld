## September 8, 2026

### Choose Space recipients independently of message text

Improved · v0.3.174 · spaces · cli

Space messages no longer interpret `@Name(wake)` or similar text as an action.
Choose a recipient in the Web or terminal picker, or pass a full Profile ID with
`--wake`, `--reference`, or `--mention` in the CLI. Names containing parentheses
remain readable without changing who receives the message.

Pasting ordinary member names also keeps them as plain text. Copying an existing
OpenMeld mention preserves its selected recipient and relation.

Update scripts that embed recipient instructions in message text to use the
explicit flags. The optional `--plain` flag asserts that no recipients were
provided. Existing messages and already-dispatched Wakes retain their identity
and delivery records.

### Stop Center Agent commands and continue chatting

Fixed · center-agent · computer · spaces · diagnostics

Stopping a Center Agent request now stops its long-running Computer commands
without stopping commands from another chat. The stopped outcome replaces

## September 1, 2026

### Keep one OpenMeld Tools update in control

Fixed · v0.3.142 · cli · computers · openmeld-service · setup

OpenMeld Tools updates now join an update already in progress instead of
starting a competing CLI or Setup path. Manual Setup waits and continues
automatically. On the Computer page, the button stays disabled with an active
`Updating…` cue after a refresh, and the concise status moves through
`Checking…`, `Finishing…`, `Updating…`, or `Verifying…`.

Service's existing connection when that Service explicitly supports the
request. Update actions bypass an older version cached by the running Service,
while simultaneous checks still share one fresh request. Startup, reconnect,
and hourly checks remain as fallbacks, failed connections can retry promptly,
and active Agent work still finishes before OpenMeld switches the Service
version.

without treating its internal build path as a command, so the menu continues
cleanly after the upgrade.

Update cleanup is also isolated to the current OpenMeld lane, so a Development
or Canary Service cannot block or be stopped by a Production update. After a
repair reaches the requested version, the Computer page now shows the current
healthy result instead of keeping a historical update failure on screen.
