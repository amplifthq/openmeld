# v0.3.247

Released October 7, 2026

## New

### Browse Spaces as cards

Spaces and Direct messages open in a card view inside your existing groups.
Switch to the table whenever you need a denser view. Both views keep your
sorting, filters, unread updates, and Space actions.

Cards show up to eight member slots and adapt to narrower widths. Unread counts
stay beside the Space name, and the latest message appears as a clean text
preview without Markdown formatting marks.

Your browser remembers the Space view you choose and each person's grouped or
expanded Agent view.

Without a saved choice, the sidebar starts collapsed on Spaces and Team overviews
and opens when you enter a conversation, person, or Agent detail page.
Your choice to open or close it stays in place across pages and reloads.

Use Show message previews in the sidebar settings to show or hide message
previews across the sidebar and cards. Previews are off by default, and your
browser remembers the choice across pages and reloads.
Rows without previews keep their titles and actions centered, and title hints
open beside the full row without covering its text.

### Choose Exo Free and Mistral Large 4 for OpenCode

OpenCode Agents can select Exo Free and Mistral Large 4 with the provider's
supported reasoning options. Mistral Large 4 requires OpenCode Zen access.
Exo Free is a preview; its provider may use data from the free period to improve
the model.

Cursor Agents gain exact options for Gemini 3.7 Flash, Gemini 3.6 Flash, Kimi K3,
GLM 5.3, and GLM 5.3 Flash. OpenCode Go's Qwen3.7 Plus now offers High and Max
reasoning. The New labels reflect the October 1–6 release batch.

Existing Agent selections and creation defaults are preserved.

### Read selected Codex session history

Computer owners can enable read-only Codex conversation history for selected
connected projects and Agents. Access starts off and works for sessions without
an OpenMeld Agent Profile. Read messages from the Computer page, the CLI, or an
authorized Agent, and check recent access on the same Computer page.

History is read on demand without syncing transcripts. File access restrictions
still apply. Agent conversations and model providers may retain returned results.
Shared Space membership alone does not grant access.

## Improved

### A clearer starting point for your first Agent

Your empty Agents section now shows a full-width card with a centered Create
Agent button. Other members' empty sections keep a simple status message.

### A simpler, customizable sidebar

The sidebar keeps its main navigation and a smaller account avatar. Open the
account menu for Search, Settings, and a compact Light, Dark, or System theme
selector. Search shows the Command K shortcut with keycaps that follow your
corner style. The same theme selector is
available in Settings > Appearance, and changing themes keeps the menu open.

Computer, Center Agent, and Inbox toolbar shortcuts now default to off. Enable
them in Settings > Appearance when you need them. Saved choices stay unchanged.

The Spaces and Team sidebar search fields stay aligned when switching sections,
without an entrance animation.

Hover over Team to jump to Agents, Plugins, Skills, Files, or Routines.
Hover over Spaces for Direct messages and Discover. Pin Direct messages to add
a compact DMs shortcut to your sidebar.
Pin the ones you use often to the sidebar, or unpin them from the same menu.
Your pins are saved in this browser. Sidebar icons now show their names as soon
as you hover over them.
The hover highlight moves continuously between primary and pinned entries,
including while a navigation popover opens or closes.

The account avatar and its hover background stay circular in every corner style.
Open Help from the account menu to see the three latest published updates,
with links to the full changelog, OpenMeld website, and documentation.
Help reads the same official updates in local development and production and
reuses recent results when reopened.
Menu focus outlines follow keyboard navigation and no longer appear from mouse
hover after reopening a menu.

### Desktop 0.1.24 Preview

Desktop 0.1.24 brings the updated sidebar, Space cards, Plugin connection status,
and Computer session-history controls to macOS and Windows x64 Preview.
It also keeps useful details when an update fails.

The macOS build is signed and notarized. Windows remains an unsigned internal
Preview with its own download channel.

### Keep Desktop update failure details

Desktop keeps a bounded local record of the latest update failure. Check for
Updates can reveal this record after a restart or a successful retry. Records
include the update stage, versions, native error code, and HTTP status when
available. They exclude raw URLs, credentials, paths, and response bodies.

### More reliable Space return visits and lighter Inbox reads

Spaces keep their recovered message position when you leave and return, avoiding
repeated catch-up failures. Opening a Space combines its access and membership
reads. Inbox reuses current Agent ownership checks within each feed request,
reducing repeated database work while keeping permissions, counts, and bulk
actions consistent.

### Quieter loading in Files and Routines

Files and Routines show simple skeletons where content is loading, keeping
navigation and available toolbar actions usable. Files no longer switches
between repeated loading messages, and background refreshes keep existing
files visible.

### Reuse Plugin accounts from Computer

Agents can reuse a connected personal or shared Plugin account for supported
native HTTP reads on your cloud Computer. Provider credentials stay on the
server, and each request checks the account's current Agent access. Cloudflare
Workers supports bounded runtime-log and invocation-metric queries, plus
deployment and version reads.

Plugin discovery and settings now distinguish expired authorization from a
stored account. When reconnection is needed, reconnect the same account in
Plugins instead of signing in again on the Computer.

Agents now receive guidance to reuse project repositories and create separate
Git worktrees for concurrent changes. Computer capability checks report
persistent storage usage and near-limit guidance before large downloads or
builds. Capacity errors explain how to preserve files and inspect the failure
without blindly repeating a command.

## Fixed

### Align development and release guidance with PostgreSQL

Default development commands start the isolated PostgreSQL product stack.
Desktop pilot builds use the shared renderer memory budget and resource checks.
Hosted releases reject unsupported PostgreSQL scopes before preparing artifacts.
Release status preserves known deployment history when impact analysis or
receipt verification remains unresolved.

### Change supported agent permissions during a task

Codex can switch between Ask for approval and Approve for me during a running
task on supported versions. Claude Code can accept an owner-selected permission
change without starting another task.

Codex settings now offer Ask for approval, Approve for me, and Full access.
Existing custom settings remain in effect until you choose another mode.
Approval cards can save a mode before continuing the approved action, with
explicit confirmation for Full access. Full access changes Codex's sandbox on
the next task; the interface explains when a change can take effect.

### Clearer Agent status and Space diagnostics

Space progress, Stop, and result commands accept copied Space links. Missing
result archives now explain that a Hosted reply can still exist and point to
the exact execution trace.

Usage Limit messages identify the reason an Agent cannot start new work.
Local CLI readiness describes local setup without promising that a Wake can
start. Pending trace projections no longer suggest an offline Computer without
evidence. Detailed traces explain the difference between completed Agent
operations and individual model-provider requests.

### Keep cloud command results available during longer tasks

Cloud Computers collect and save command results while an agent works on other
steps. A completed result remains available after the runtime removes its
temporary command log. File synchronization must be confirmed before a command
reports completion.

An agent can recover from a reported command loss without the same error
discarding its final response. Interruption notices use simpler instructions and
no longer direct you to an unspecified Diagnostics screen.

### Keep conversations stable when switching Spaces

Returning to a Space keeps received Agent progress in view. An open Thread
reserves its place while messages load, and visible work no longer briefly
appears again beside the composer. Received reply text stays readable without
replaying a blur effect when you return.

Pending actions use a yellow status dot instead of red. Responding to an Agent
approval or question immediately updates the Space's attention indicator.

### Keep staged Service releases on the published CLI version

Combined Remote Agent and Local Service releases keep Core's version declaration
on the published CLI until the new CLI artifacts are available. Operators can
complete the PostgreSQL cloud stage locally and then use GitHub's signed CLI
publication workflow.

### Keep unrelated MCP discovery out of Codex task startup

With Codex 0.160.0 or later, OpenMeld checks its own tool connection without
opening extra connections to unrelated tool services. A stalled extra connection
no longer blocks an ordinary task before it starts. Your configured tools and
file access settings stay in place. Tasks with explicit isolation still receive
the full isolation check.
