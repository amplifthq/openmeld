# v0.3.251

Released October 10, 2026

## Improved

### Connect Plugins and review Agent access in a conversation

When an Agent needs a Plugin account or permission, you can open the existing
connection and access controls from its message. Save the access you choose,
then continue the original task there. New connections grant no Agent access
until you approve it.

Slack joins the featured Plugin catalog. Slack, Lark, and Feishu use the live
OpenConnector configuration for sign-in readiness. A missing OAuth client now
shows a clear setup message instead of offering a connection that cannot start.

### Consistent conversations and Thread replies

Thread replies share Profile cards, message tools, quoted replies, queued
follow-ups, unread navigation, and Jump to latest with the main conversation.
Queued replies stay in their original conversation. The composer work shortcut
also finds queued replies in closed Threads and opens
the right Thread, alongside other work outside your view. Full-width messages
reserve room for avatars on both sides, so long messages have matching content
edges.
Members can open an existing Team Brief, while creation stays with owners and
admins.

Center Agent Profile cards show the model and a cloud icon, with a direct
settings action. Routine availability and default reasoning labels are omitted.
App Settings also omits the routine Available label.
Bot avatars in Profile cards look around, follow the mouse, and play a full
spin when clicked. Conversation avatars retain their small click hop.

### Keep Agent capabilities when choosing a separate working copy

Choose a separate working copy without adding extra restrictions to your Agent's
tools or permitted network access. Working copy and Access are separate choices
in the Agent menu, and CLI Project selection keeps Agent settings by default.
Choose Session → Automatic to clear those task choices and return to automatic
continuation. An existing session keeps its own restrictions.

OpenMeld manages the copy and retains unfinished changes. Computer file policies,
native approvals, and explicitly restricted tasks continue to apply. Forking an
independent task keeps its separate-copy mode.

### Manage Spaces and Direct Messages with consistent controls

Newly joined Spaces appear immediately with a New indicator until opened, even
when they have no messages. Message badges count actual unread messages.
Pinning and dragging respond immediately. Discover shows member
avatars and a read-only preview; joining opens the full Space.

Adding a third participant turns a Direct Message into a Space permanently.
Personal Spaces settings let you choose whether messages automatically Wake the
Agent when you are the only Human with one Agent.
Conversation layout, message placement, and the history slider are now under
Personal Spaces settings, with visual choices. Message previews share the same
setting as the conversation sidebar.
You can also choose Enter or Cmd/Ctrl+Enter to send messages, including in
Direct Messages and threads.

When an Owner deletes a Space, its members can still read and search its history.
The Space shows a small Deleted label and accepts no new messages or Agent work.
Members can remove it from their own lists. Archived Direct Messages also offer
Delete for me, which clears the person's history without affecting other people.

### More models for OpenCode agents

OpenCode agents can select Step 5 Preview Free through Zen or Go, plus additional
Zen models from Anthropic, OpenAI, Google, DeepSeek, xAI, and Meta. Each model uses
its native reasoning options. Provider access is still required where applicable.

GPT-5.3 Codex Spark now shows its confirmed retirement for ChatGPT sign-in. API-key
access and existing model selections retain their identity.

Plugins adds Google Sheets, Docs, Slides, Forms, Analytics, Search Console,
Meet, and Ads, plus Vercel, HubSpot, Airtable, Supabase, Outlook, Resend,
Meta, Mailchimp, and Canva. Sign-in availability depends on the OAuth setup

The catalog also includes Neon, GitLab, Docker Hub, Sentry, Dropbox, ClickUp,
monday.com, Asana, Miro, Intercom, Zendesk, Shopify Admin, Confluence, Trello,
Jira, and Stripe. Shopify Admin uses the current Admin GraphQL API for
products, inventory, fulfillment, orders, and customers. Stripe actions cover
customers, products, and prices.

Cloud services add AWS S3, Alibaba Cloud OSS, SLS, and ACK, plus Cloudflare
Docs, Email Routing, and MCP. Microsoft adds Excel, Teams, OneDrive, Outlook
Calendar, and Clarity. Zoom, Box, and Datadog are also listed. Cloudflare Docs
connects without account credentials; you still choose which Agents can use it.

Discord Bot uses your own Bot Token to read channel messages, send messages,
and manage servers where the bot is installed. It is available under Personal
and organization accounts. This Plugin does not add Discord to Channels.

The website lists all supported Plugins and distributes their distinct logos
evenly across two scrolling rows. Reduced motion shows every logo in a static
grid. The headline connects Plugins to team workflows, and long names stay
centered when they wrap.

Browse Plugins by category, open a category to see all its tools, and search
beside the Personal and organization tabs. Cards show what each tool does,
with connection status kept on one line.

Switch between Personal and organization accounts within Plugin details.
Reconnecting an expired account keeps the sign-in window open until the
connection is renewed, instead of reporting success from the old connection.

Gmail, Outlook mail and calendar, Google Calendar, Google Meet, and Zoom connect under
Personal. You choose which Agents can use your account. Older organization
connections for these services are disabled and remain available to disconnect.

The homepage demo opens billing review in a readable Thread panel alongside the
main conversation and Members. Compact navigation shows complete Space names,

### Understand a Wake's task access and start fresh

Message details explains a Wake's task access, working-folder selection, and
whether its Agent conversation started fresh or continued. A Space-only task
lets members with message permission review and send the visible request as a
new task under their own profile, using their permissions and the Agent's
current permitted settings. Reopening or retrying the same recovery
does not create another task.

The Agent's Session options clarify that automatic continuation keeps earlier
restrictions.
CLI diagnostics can read retained task settings after the transient execution
record has retired, while older trace clients keep their existing response.
When task settings cannot be read, Message details shows that they are
unavailable. A recovery cannot use another sender's publication receipt.

## Fixed

### Check each receiver contract before a production release

Production release checks require evidence for every changed receiver contract.
An unchanged AI usage receiver can be verified from its recorded deployment
source, while other pending contracts still require their own evidence or a
receiver deployment. This prevents one compatible contract from admitting
unverified changes between the same services.

Center Agent working-folder updates require the new Core receiver to deploy
before their Remote caller. Unrelated AI usage evidence cannot admit these
updates while that receiver is still pending.

Agent setup and folder recovery also wait for their Database, Auth, Core and
Gateway receivers. Cloud command references and detailed lists require Core
and Remote Agent before Gateway exposes them, then Gateway before the CLI.
The checks apply to caller-only changes and reject unavailable source evidence.

Saved working-folder reads require Core before the new Service registration,
Core's read methods before Gateway, and Gateway's GET routes before Web.
Other folder or runtime evidence cannot substitute for this read contract.
Workspace initialization also requires Core before the Service advertises its
strict initialization capability, including a Service-only source change.
Initialization and read proofs must each cover their own contract.

### Keep existing Spaces readable after an update

Existing Spaces apply the database upgrade for deleted Space history when they
next open. Their members, settings, and messages remain available. Repeated
starts preserve the saved history and deletion state.

### Keep proactive reports and Task reviews visible

Proactive Agent reports, Routine results, and formal system outcomes now create
unread updates for the conversation's recipients. Reading a message before Inbox
finishes syncing keeps it read after synchronization.

Space Tasks awaiting a Human review or rework decision now remain in Inbox until
the Task's own workflow ends the request. Reading messages or dismissing an Inbox
item does not approve the result.

### Keep sidebar lists readable while resizing

Contextual sidebar lists stay at their minimum readable width while you drag
inward. The minimum width is more compact. Collapse requires another third of
that width plus a small buffer, which prevents small drag movements from hiding
the list. A shorter outward drag reopens it. Dragging and keyboard resizing no
longer leave a squeezed icon-only state. Longer names stay on one line with an
ellipsis, and edge hover still reveals a temporary preview.

### Keep Space permission errors clear

When a Space denies a visit activity update, OpenMeld now reports a permission
error instead of a service connection failure.

### Keep the original time for delegated requests

Delegated tasks and follow-up work keep the original request's time and timezone.
Relative instructions such as "in ten minutes" use the same starting time after
a task completes or its follow-up request retries.
Local Agents also receive this time reference when their work starts later.

### Keep worktree Workers running when Web restarts

Worktree development starts the Worker stack separately from Web. Restarting
Web or switching to the compiled Desktop pilot preserves the running Workers
and local database. Use `pnpm desktop:web` after starting the worktree stack
to run the matching compiled pages for Desktop.

### Open newly created Agents without waiting for background refreshes

After an Agent is created, its details open without waiting for background
directory and availability refreshes. Those refreshes still run so the Agent
appears in selection lists.

Working folder settings can save the displayed choice even when it has not
changed, allowing you to apply the configuration again when the local folder
has not been initialized. Changes remain unavailable while the Agent is working.

Reopening Working folder loads the saved folder choice from the Agent's
Computer. Changing that Computer while settings are open keeps your draft and
asks you to reopen settings before saving. Folder paths retain meaningful
spaces and Unicode characters.

Folder errors now open Working folder settings from both Profile and Space
recovery. Missing or stale local-agent reports lead to Computer status rather
than another connection flow.

Update Local Agent opens the affected Profile so its bound Computer and Agent
remain available. Computer status actions still open Computer settings.

Newly imported local conversations keep the folder observed during import.
If that folder disappears, settings explain how to restore the original worktree
or choose a folder for new work. OpenMeld does not replace the saved folder
automatically, and a later manual choice survives import retries.

### Recover Space watches after a connection drops

Space watches reconnect after a temporary connection failure and load missed
messages without displaying duplicates. The existing view stays open during
recovery. Recovery never resends a message or starts another Agent task.

A watch reports failure when recovery cannot finish, so scripts can detect an
interrupted stream. Leaving the watch yourself remains a normal exit.

### Report failures before delegated work starts

When a delegated Wake fails before execution starts, its task now receives the
saved Space result. Center Agent can continue with that failure instead of
waiting for an execution that never started. Recovery keeps existing successful
or stopped results.

## Security

### Keep customer conversations out of routine diagnostics

For customer organizations in production, model logs keep usage and status
information without a copy of the conversation. Automatic agent feedback sends
problem categories and diagnostic IDs instead of generated summaries or details.
User-submitted feedback still includes the information you choose to share.

Diagnostic Report IDs resolve through the current database to compact execution
traces. Authorized infrastructure operators can still investigate stored content
with your consent. Task execution and conversation history remain available.
