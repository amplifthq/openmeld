# v0.3.132

Released August 30, 2026

## Improved

### Find people and their computers together

People now keeps Human Profiles in a dedicated sidebar and opens each person's
full details in the main view. Computer cards live with their owner, invitations
share one dialog, and the current Computer is always one click away from the
bottom toolbar. Computer status now follows the current OpenMeld Service
connection, so a registered Computer never looks ready only because OpenMeld
has seen it before.

The People sidebar now groups teammates as **Connected** or **Not Connected**
based on whether they have connected a Computer, with plain-language tooltips
for both labels. Your own profile stays first, while teammates in each group are
ordered by when they were last seen in OpenMeld Web. Activity uses compact copy
such as **3 hours ago**, explains **Last seen 3 hours ago** on hover, and sits on
the same row as Local Agent icons. Empty Channel rows no longer reserve space.
Opening or returning to OpenMeld Web now refreshes your last-seen time; using the
CLI alone does not.

## Fixed

### Always copy a fresh Agent Interface prompt

Agent Interface now replaces expired one-time setup credentials before Copy
writes the prompt to the clipboard. The button waits for a complete fresh
prompt and can be retried in place, so users no longer copy a command that
OpenMeld already knows will fail.

### Find the conversation with unread messages

Direct Messages now show unread attention on the exact conversation that needs
it. OpenMeld also keeps read positions durable and prevents a main-conversation
read from hiding an unrelated thread item, so a failed update or unrelated read
cannot silently hide a later message.

### Keep Computer details honest while they refresh

Opening a teammate's Computer now waits for a fresh Organization Computer
projection before deciding that the Computer no longer exists, so an older
cached list cannot briefly hide required update guidance.

### Keep pending Service updates on the newest version

When a newer OpenMeld Service version becomes available while an update is
already waiting, OpenMeld now replaces the older target with the newer version.
The existing update remains recoverable until the newer target is safely saved,
and an older worker or queued request cannot overwrite that target or move the
Service back to an earlier version.

### Keep your Computer connected when setup cannot finish

Connect Computer now gives the Computer its own sign-in, verifies that Web and
the setup command belong to the same account, and keeps the existing Computer
connection working when a new setup attempt fails, is canceled, or is interrupted
by a closed Terminal, process crash, or computer restart. Switching a Computer
to another account also requires explicit confirmation. That confirmation stays
bound to the exact Computer sign-in the user reviewed. If another process
changes the sign-in before setup starts the switch, OpenMeld
stops and asks the user to review again. The new candidate sign-in remains
private to setup and its candidate Service until Prepare succeeds. If setup is
interrupted while OpenMeld Service is already offline, a fresh repair can now
restore the previous Computer connection instead of getting stuck on a missing
local control socket. If account validation offers a refreshed token while that
recovery is still in progress, OpenMeld keeps the restored sign-in untouched
until Service repair finishes. Recovery also closes the unused temporary
sign-in correctly, so later status and repair checks do not leave the
interrupted handoff deferred.
Sign-in and Service status remain available for diagnosis. CLI and OpenMeld
Service requests now refresh an expired local session when possible, then stop
locally with clear auth diagnostics instead of continuing without authentication
when stored credentials are expired or malformed.

### See how a Space can be found and opened

OpenMeld CLI now separates Organization visibility from link access in Space
lists and status output. An invite-only Space is no longer mistaken for
members-only when anyone with its link can open it.

### Send multiple files reliably from the CLI

CLI users and Local Agents can share up to ten files in one Space message
without the second upload colliding with the first. If a later upload fails,
OpenMeld moves files already added by that send to recoverable Trash and gives
exact cleanup guidance if any file could not be moved. CLI help and the official
OpenMeld Skill now consistently use `--file` for shared files and `--text-file`
for a UTF-8 message body.

### Show when a local agent is truly unavailable

Local agents that are signed out or blocked by provider access now appear as
Unavailable instead of a red launch error. Computers and Agent Profiles use the
newest exact local runtime evidence, distinguish temporary rate limits from
hard account or quota blockers, and point to the provider action needed before
the agent can run again.
