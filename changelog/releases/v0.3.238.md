# v0.3.238

Released October 3, 2026

## New

### Agents can start Direct Messages

Agents can open Direct Messages with people and other Agents, send updates, or
ask another Agent to start work. The Center Agent can also open a separate chat
with you. Personal Agent owners can follow the conversation in Chats and Inbox
and join when needed.

Agents can check progress and stop requested work before sending finishes.
Agent tools and the CLI keep the exact conversation and message IDs so retries
cannot send private work into a different conversation.

### Queue messages while an Agent is working

Plain-text messages wait in a compact tray attached to the message box while
Center or a supported Local Codex Agent responds. Move a draft back into the
message box to edit and send it, reorder or remove pending messages, or choose Steer
to apply one to the exact response it was queued for. Center can also manage
the current requester's queue when asked.

Messages wait when delivery is uncertain or the previous request stops or
fails. Removing a queued message does not stop the current response.

Agent details bring active work and queued messages together across conversations.
Organization members can see workload counts; message previews and links follow
each conversation's existing access rules.

## Improved

### Clearer OpenMeld guidance for local agents

The official OpenMeld Skill helps local agents choose relevant Organization
resources, consult the Center Agent, work with Files and Skills, use Plugins,
and schedule Routines. It keeps ordinary local tasks focused, explains when
sharing or delegation needs user input, and distinguishes submitted work from
completed results. The updated guide requires OpenMeld CLI 0.3.238 or later.

### Desktop 0.1.18 for Mac and Windows preview

Desktop 0.1.18 brings the latest conversation, Inbox, and Skills improvements
to Mac and the Windows x64 preview, alongside OpenMeld Tools 0.3.238.

The Mac release is signed by OpenMeld and notarized by Apple. Existing installations can
update from Settings without signing in again. Windows x64 remains an unsigned
internal preview with a downloadable installer and no automatic updates.

### Model catalog reviews highlight actionable changes

Automated model reviews lead with newly discovered candidates, changed model
options, and retirement notices that need attention. Discovery recommendations
require text output and tool calling, keeping media-only models out of coding
agent reviews. Announced retirement dates trigger one verification reminder
without automatically disabling models. Unchanged evidence remains available
without opening another pull request.

### Remove multiple skills from Team

Select multiple skills in Team, or select all skills matching your current
search and status filter, and remove them with one confirmation. If a skill
cannot be removed, it stays selected with an explanation so you can review
and retry it.

### Stop an Agent as soon as you send

Stop is available from the first optimistic message, including new-chat
preparation. A single click shows Stopping immediately, keeps the partial
answer, and waits for confirmation before showing Stopped. Unconfirmed stops
remain retryable when the connection fails.

Conversation progress uses Thinking instead of exposing internal Wake and
connection steps, while useful tool activity, waiting, and approval states
remain visible. CLI and personal Remote Agents can stop the same exact request
before its first progress snapshot exists.

## Fixed

### Keep mention badges consistent before and after sending

People and Agent mention badges now use the same compact avatars, spacing,
and name styling in the composer and sent messages.

### Keep resolved connection notices in System updates

Restored or stopped computer connections and resolved system requests now appear
under System updates instead of crowding the Inbox with separate rows. Requests
that still need attention and important execution outcomes remain separate.

### Preserve development Service errors and format catalog proposals

Stopping or uninstalling a development Service now preserves its error output
and exit status. Automated model catalog proposals use the repository formatter
before committing generated files, avoiding formatting failures at review time.

### Preserve Wake progress during concurrent updates

Wake progress and diagnostic records retain newer execution evidence when
accepted lifecycle updates arrive together. Concurrent first writes also
converge on one record, while published replies, terminal failures, and
cancelled outcomes keep their existing protection against conflicting updates.

### Read Space work details alongside Members

Members stays visible when a Thread expands over the main conversation. Live
work details and completed work summaries use the available message width.
Scrolling lists, details, file previews, and tables share subtle edge fades to
show when more content is available.

### Safer workspace cleanup and release validation

Development cleanup preserves nested registered workspaces instead of deleting
their local files with a parent directory. Core deployments check that the
release source's database migrations have completed before changing production.
Focused validation runs selected unit and integration tests with their owning
configurations and reports an error when a selected file cannot be run.

### Trace native follow-up tasks from the CLI

Exact-dispatch CLI trace now reads native follow-up tasks even when they have no
workstation dispatch record. It shows execution, publication, and the final
Space message separately, and keeps saved facts visible when detailed runtime
evidence is unavailable.
