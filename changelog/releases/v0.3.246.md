# v0.3.246

Released October 7, 2026

## New

### Connect OpenCode 2 and Antigravity ACP

Local agents can use OpenCode 2 or the official Antigravity ACP installation.
Both support continued conversations, native tools, permission requests, and
questions through the existing OpenMeld controls. Existing OpenCode 1 and
Antigravity CLI installations remain supported.

Antigravity status checks do not start sign-in. A connected provider account is
still required to run its models. Automatic reply repair remains unavailable
for these two new transports until their tool restrictions can be verified.

### More OpenCode model choices

Local Agents can select Ling 3.1 Flash Free through OpenCode or Space Bunny
through OpenCode Go, with their supported reasoning efforts. The Go route
requires an active OpenCode Go subscription.

The former Go Space Bunny Free route is unavailable. Existing selections stay
unchanged so you can choose another model. The separate OpenCode Space Bunny
Free route is still listed.

## Improved

### Browse grouped updates from the Inbox toolbar

The Inbox toolbar now shares the full Inbox's conversation and system-update
groups. Scroll to load older items, expand a group, or mark it as read without
leaving your work. Pending requests stay visible after reading, and the full
Inbox remains one click away. Loading failures offer a retry without discarding
updates already on screen.

### Faster Center Agent settings

Center Agent settings load without waiting for every Agent in the workspace.
Model and organization memory settings load in parallel with identity, and
reopening settings keeps the previous values visible while they refresh.

### Faster organization reads and clearer chat recovery

Space member details and Inbox updates load with fewer sequential waits.
Activity, project, and usage reads do less database work. Team skips live
computer checks for members who have no registered computer.

Unavailable Center Agent chats now offer a fresh retry and a link to your own
chat. Short-lived live connections back off instead of repeatedly reconnecting
at the fastest rate.

### Keep hosted agents on track after context compaction

Center Agents and hosted Remote Agents can recover their most recently selected
tools and available retained results after a conversation is shortened. Context
compaction reserves room for new work and uses one summary request per working
checkpoint. Computer tasks keep their existing identity for progress checks,
result retrieval, and cancellation.

### Keep your selected page tab on refresh

Routines, Files, Plugins, Spaces, Inbox, Skill content, and Usage keep the selected
tab in the page address. Refresh or use browser back and forward to return to
that view. Switching Skill content tabs keeps unsaved edits in place.

Trash keeps its selected background when a Files location is hidden.
Files and Routines keep their tabs aligned when switching pages. The Files
toolbar now uses distinct icons for list and columns views.

### Manage personal and team routines in one place

Routines now lives under Team. Create personal or shared scheduled work for a
Center, Remote, or Local Agent, then manage its schedule and results from one
list. Local work runs directly on the selected Agent's computer.

The editor uses simple schedule controls, searchable Space and timezone pickers,
and clear result destinations. Personal definitions and run history stay private.
Self-Evolution recommendations are hidden.

Open Run history from the list to see each run's status and destination. View
result takes you straight to its published answer, including older runs sent to
a different Space. Last run shows a compact 24-hour time first, followed by its
status. A green time with a check opens a completed answer directly.

Pause or resume directly from each row. See where results go and who created
each team routine. Filter by status or sort by next run, recent updates, or name.

Personal and Team use the same compact tabs as Files. Search, filters, and
Create share one toolbar without a repeated page title.

### Quieter Space recovery

Space titles no longer show loading, reconnecting, or syncing badges. Brief
interruptions recover quietly. If updates remain interrupted, a discreet notice
in the conversation explains that messages and activity may be out of date and
offers Retry. Existing messages and drafts stay in place.

Live Agent work also stays visible while the same conversation reconnects.
Thinking and progress recover independently, and returning to a suspended tab
checks the connection before replacing it.

### Reduce repeated context in local Agent conversations

Local Agents with verified native instruction delivery receive fewer repeated
completion rules on each Wake. The current request, permitted actions, and
task facts remain in every turn. Existing conversations without matching
instruction evidence keep the complete prompt.

Local Agents can also search large Space tool results for exact text and read
the surrounding original content. Complete results remain available through
paging, and every read checks source access and version again.

### Reduce repeated tool output in hosted agent context

Hosted agents can omit older completed tool-output previews when their working
context is full. They keep completion details and references for reading the
original output when needed. Recent results stay visible, and normal history
compaction still runs when the context needs more space.

### Send extra instructions while Claude Code is working

Claude Code can receive queued instructions during a running task through the
same Send now action as Codex. OpenMeld waits for Claude to confirm receipt
before showing the message as sent. This requires Claude Code 2.1.290 or later.

Replies no longer show an outdated-message notice for instructions confirmed
as delivered to that same running task. Local agent capability reports also
reflect the approval and question flows already supported by their adapters.

### Use connected accounts with native Git

Agents can clone and fetch private GitHub repositories on your cloud Computer
through an existing personal or organization Plugin connection. Git transfers
the repository directly. Provider credentials stay inside OpenConnector.

The Plugin catalog now uses each provider's available connection methods,
including alternate credential methods and multiline keys. New providers do not
need a separate OpenMeld service list entry.

Action execution requests metadata by exact Action ID instead of transferring
the full service catalog when the connector supports the filter.

### Use native tools on your cloud Computer

Center, Remote and Local Agents can use the same file tools, Linux programs,
fast shell and isolated JavaScript on your personal cloud Computer. Each engine
can access the network and work with your persistent files. Commands support
environment variables, input and results. Linux and Worker JavaScript support
retained execution and cancellation. The lightweight shell runs to completion.

Local Agents can inspect available capabilities with `openmeld computer cloud
--operation '{"action":"describe"}' --view agent`. Browser and private preview
operations use the same interface when available. Account connections still use
Plugins; no additional authorization screen or virtual desktop is introduced.

## Fixed

### Clearer AI usage charts

Usage charts keep Claude orange and GPT blue-purple, matching their Local Agent
colors. Model variants stay within their brand's color family when you switch
between Organization and My agents, change the date range, or view a Computer.
Chart lines, legends, and tooltips use matching colors in light and dark themes.

The settings sidebar and page now use the name AI usage. Organization usage
shows the workspace total, while My agents includes both Remote Agent costs
and Local Agent tokens for your agents.

Routine counts move out of AI usage and appear beside the Routines page title
as a compact count, such as 3/50. Hover over or focus the count to see the limit.

### Keep Agent progress steady across Space and Thread views

Agent progress and available Stop controls stay visible when you jump to a
message or open its Thread. Active requests use one Working status instead of
switching between similar labels. Known live work remains visible while Thread
history loads, and messages load independently of progress updates.

### Keep writing while a Space loads

Start a draft as soon as a Space opens. The message editor stays in place while
messages and members load, so loading does not interrupt typing or reset the
cursor. Switching Spaces keeps each conversation's draft separate. Sending
still checks current access before posting.
