# v0.3.263

Released October 16, 2026

## Improved

### Clearer setup guides and product answers

The website now includes answers about working with existing agents and
self-hosting, with links to the first-task guide and deployment limits. FAQ
answers are available when the page first loads.

The seven local-agent guides explain how to connect each tool and share task
results. The Codex guide also links to access and tool-permission guidance.

### Find your Agents in the team directory

Switch between My Agents and All Agents in Team's existing Agents page. Open an
Agent's profile and settings, then return with your view, search, and filters
preserved for the current workspace.

### Open Routines directly from the main navigation

Routines has its own main navigation entry for personal and shared scheduled
work. Team keeps People, Agents, Files, Skills, and Plugins together.

Sidebars now match the page: People shows members, Agent details show the
current Agent list, and Files shows file locations. Skills, Plugins, and
Routines keep their own search and filters without an unrelated member list.

Spaces and Team sidebars share compact headings and collapse controls. Choosing
a file location returns to its root, and switching Agents preserves the return
path to the Agent directory.

Files keeps view, sort, filter, and search controls together on the left, with
New on the right. File destinations appear directly below the sidebar heading.

Spaces and People keep search in their sidebar options menu until needed, then
focus the revealed field. People options group computer filters in a submenu
and remove the five-minute activity filter. Sidebar icons and labels align with
their shared headings. A small Close search icon clears and hides the field;
Escape does the same and returns focus to the options button.

Newly pinned conversations appear first in Pinned, keeping the existing order
of other conversations. You can still drag pinned conversations to reorder them.
Smaller pinned avatars and a two-to-five-column grid fit more conversations
in the sidebar, including Spaces with multiple members.

### Search messages across Spaces with less waiting

Message searches across many Spaces spend less time waiting for each conversation
to respond. Web, Desktop, and Agent message reads use the same improved reader,
with the existing access checks, result order, and complete pagination.

### Switch Spaces with less sidebar work

Switching between Spaces keeps the conversation sidebar in place and avoids
rebuilding unchanged rows. This reduces navigation delays in Web and Desktop,
especially when your sidebar contains many conversations.

## Fixed

### Clearer Space addressing and task continuation

The CLI catches repeated leading recipient names before sending. Continue or
fork a task from its original request or an Agent reply with recorded task
details. Reply threads remain a separate choice.

When a selected task is unavailable, OpenMeld explains how to select another
source or start a new task instead of reporting a model-provider outage.

### Keep delegated work connected to its Task

Delegating an existing Space Task records its assignee and reviewer together
with the work request. Agents receive the same Task through implementation,
result submission, review, and requested changes. Task progress remains separate
from execution status, and a missing reviewer is reported instead of silently
dropping the requested review.
Handoffs reach only their intended Agent, including in Spaces using listen-all,
and unrelated Project or issue updates do not discard a pending work request.

### Keep full-width Space messages aligned

Full-width Spaces keep message avatars and the composer aligned with the header,
with consistent side spacing whether the history slider is visible or hidden.
Touch layouts hide the history slider. Thread spacing is unchanged.

### See new Agents in the member picker immediately

New Local and Remote Agents appear checked at the top of their owner's list
while creation finishes. Clearing the selection stays respected when the Agent
is ready. Failed creations no longer block adding other members. After Grok Bot
sign-in, Agent creation updates in the same dialog.
The Service collects new connection evidence after setup instead of reusing a
check that started before sign-in finished.

## Security

### Harden Grok configuration parsing

Grok reply correction uses an updated configuration parser that fixes excessive
processing time for large TOML files. Existing configuration values and permission
restrictions remain in effect.

### Update request handling, rendering, and dependency security fixes

Update the libraries used for Lark message encoding and decoding, Remote Agent
input validation, YAML parsing, static HTML previews, and Auth, Core, and Desktop
builds. These updates include upstream security fixes in protobufjs, Valibot,
yaml, DOMPurify, esbuild, and Vite. Existing message formats and tool inputs
remain unchanged.

Update Hono request handling and React rendering across Web, Desktop, Website,
Docs, and shared UI. Preserve route parameter types in extracted handlers and
reject missing avatar and organization logo filenames through existing validation.

Update Desktop to Electron 44.7.2, including upstream macOS background-click and
interrupted-update fixes. Keep the existing login, permissions, and update policy.

## Breaking

### Use Node.js 22, 24, or 25 for the npm CLI

The npm CLI requires Node.js 22, 24, or 25. Node.js 24 is recommended.
npm-based setup and CLI startup explain how to select a supported Node.js version.
Node.js 23, versions below 22, and versions 26 or later are unsupported. Direct npm installation
only warns by default; native dependency installation can fail before OpenMeld runs.
Use Node.js 24 before installing the npm CLI.
The standalone OpenMeld CLI includes its own runtime. Default macOS Web setup
installs it as a managed binary and does not require a Node.js upgrade.
